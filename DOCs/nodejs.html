1

¿Qué es Node.js y por qué lo usamos?

Node.js es un entorno de ejecución de JavaScript que funciona fuera del navegador, directamente sobre el sistema operativo. Permite construir servidores web, APIs y aplicaciones de red usando el mismo lenguaje que se usa en el frontend.

ConceptoExplicación sencillaAnalogía
Node.jsMotor que ejecuta JavaScript en Windows, Linux o Mac sin un navegador.Como Java pero para JavaScript
npmNode Package Manager — el gestor de paquetes incluido con Node.js.Como pip en Python o NuGet en .NET
package.jsonArchivo de configuración del proyecto: nombre, versión y dependencias.Como un manifiesto del proyecto
node_modulesCarpeta donde se guardan los paquetes instalados con npm.Como la carpeta vendor en PHP
ExpressFramework web minimalista que facilita crear rutas y un servidor HTTP.Como Flask en Python
oracledbDriver oficial de Oracle para Node.js. Permite conectar la app con Oracle XE.Como un conector JDBC pero para JS
En este proyecto, Node.js actúa como el servidor web: recibe las peticiones del navegador, las procesa, consulta Oracle XE y devuelve los resultados en formato JSON o HTML.
2

Requisitos previos

  • Windows 10 u 11 de 64 bits (versiones de 32 bits no son compatibles con oracledb).
  • Conexión a Internet para descargar Node.js y los paquetes npm.
  • Cuenta con permisos de administrador para ejecutar el instalador MSI.
  • Oracle XE 21c instalado y con el servicio XEPDB1 activo (requerido en la Fase 1).
  • Un editor de texto o IDE: se recomienda Visual Studio Code.
Instale Node.js antes de intentar conectarlo con Oracle. Confirmar que Node.js funciona solo simplifica enormemente la resolución de problemas.
3

Descarga de Node.js LTS para Windows

3.1 Elegir la versión correcta

Siempre descargar la versión LTS (Long Term Support), no la "Current". La versión LTS es la más estable y la recomendada para proyectos académicos y productivos.

Sitio oficial: nodejs.org → botón verde grande que dice "LTS — Recommended For Most Users".

3.2 Archivo a descargar

ArchivoCuándo usarlo
node-v##.##.#-x64.msiInstalador estándar para Windows 64 bits. Usar este.
node-v##.##.#-x86.msiSolo para Windows 32 bits. No compatible con oracledb.
node-v##.##.#-win-x64.zipVersión portable sin instalador. No recomendada para clase.

3.3 Verificar si ya está instalado

Antes de descargar, verificar si Node.js ya está instalado en el equipo del laboratorio:

PowerShell — Verificar instalación existente
# Verificar versión de Node.js
node --version

# Verificar versión de npm
npm --version

# Ver ruta del ejecutable
where.exe node
where.exe npm

Si ambos comandos devuelven una versión (ej. v20.11.0 y 10.2.4), Node.js ya está instalado y puede saltear a la sección 5.

4

Instalación de Node.js en Windows

  1. Ejecutar el archivo .msi descargado. Si Windows solicita permisos de administrador, aceptar.
  2. En la pantalla de bienvenida, hacer clic en Next.
  3. Aceptar el acuerdo de licencia y hacer clic en Next.
  4. Mantener la ruta de instalación predeterminada (generalmente C:\Program Files\nodejs\).
  5. En la pantalla de componentes, dejar todas las opciones marcadas. No desmarcar nada. El instalador incluye Node.js, npm y la configuración automática del PATH.
  6. En la pantalla "Tools for Native Modules", NO marcar la casilla si no tiene Visual Studio instalado. Esta opción no es necesaria para este proyecto.
  7. Hacer clic en Install y esperar a que finalice.
  8. Hacer clic en Finish. Cerrar y volver a abrir PowerShell para que el PATH se actualice.
El instalador MSI configura automáticamente la variable de entorno PATH para que node y npm sean reconocidos desde cualquier carpeta en PowerShell.
Si abrió PowerShell antes de instalar Node.js, debe cerrar esa ventana y abrir una nueva. Las sesiones abiertas no detectan cambios en el PATH.

Verificación de la instalación desde PowerShell

Abrir una ventana nueva de PowerShell y ejecutar los siguientes comandos de verificación:

PowerShell — Verificación completa del entorno Node.js
# 1. Versión de Node.js instalada
node --version

# 2. Versión de npm instalada
npm --version

# 3. Ruta del ejecutable de Node.js (debe mostrar la carpeta de Program Files)

# 4. Ver variables de entorno relacionadas a Node
[Environment]::GetEnvironmentVariable("PATH", "Machine") -split ";" | Where-Object { $_ -like "*node*" }

Resultados esperados:

v20.11.0
10.2.4
C:\Program Files\nodejs\node.exe
Si los tres comandos devuelven resultados similares, Node.js está correctamente instalado y listo para usarse.

Primer servidor "Hola Mundo" — sin Oracle

Antes de conectar con Oracle, verificar que Node.js puede levantar un servidor HTTP por sí solo. Este paso confirma que el entorno funciona correctamente.

6.1 Crear la carpeta y el archivo

PowerShell — Crear proyecto de prueba
# Crear una carpeta de prueba
New-Item -ItemType Directory -Path C:\prueba_node -Force
cd C:\prueba_node

# Inicializar el proyecto (crea package.json)
npm init -y

# Crear el archivo del servidor
notepad hola.js

6.2 Contenido de hola.js

JavaScript — hola.js · Servidor HTTP mínimo
// Módulo http incluido en Node.js (no requiere npm install)
const http = require('http');

// Definir el puerto donde escuchará el servidor
const PUERTO = 3000;

// Crear el servidor: recibe una petición y devuelve una respuesta
const servidor = http.createServer(function(peticion, respuesta) {
    respuesta.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    respuesta.end('<h1>Hola Mundo desde Node.js</h1><p>El servidor está funcionando.</p>');
});

// Poner el servidor a escuchar en el puerto definido
servidor.listen(PUERTO, function() {
    console.log('Servidor iniciado en http://localhost:' + PUERTO);
    console.log('Presionar Ctrl + C para detener.');
});

6.3 Ejecutar y probar

PowerShell — Ejecutar el servidor de prueba
# Desde la carpeta C:\prueba_node
node hola.js
Servidor iniciado en http://localhost:3000
Presionar Ctrl + C para detener.

Abrir el navegador y visitar http://localhost:3000. Debe aparecer el mensaje "Hola Mundo desde Node.js".

Si el mensaje aparece en el navegador, Node.js está instalado y funciona correctamente. Puede pasar a configurar el proyecto real.

Estructura del proyecto WEB

La estructura de carpetas organiza el código del proyecto. Seguir esta convención facilita el trabajo en equipo y la corrección del docente.

PowerShell — Crear la estructura de carpetas del proyecto
# Crear la carpeta raíz del proyecto
New-Item -ItemType Directory -Path C:\proyecto_web -Force
cd C:\proyecto_web

# Crear subcarpetas
New-Item -ItemType Directory -Path js     -Force  # Código del servidor Node.js
New-Item -ItemType Directory -Path public -Force  # Archivos HTML del cliente

# Inicializar npm dentro de la carpeta js
cd js
npm init -y

El resultado debe tener esta estructura:

C:\proyecto_web\
├── js\ ← Código del servidor (Node.js)
│ ├── server.js ← Punto de entrada: arranca el servidor Express
│ ├── package.json ← Dependencias y scripts (generado por npm init)
│ ├── .env ← Credenciales Oracle (NO subir a Git)
│ └── node_modules\ ← Paquetes instalados (NO subir a Git)
├── public\ ← Archivos HTML que ve el usuario
│ ├── login.html ← Pantalla de acceso
│ ├── menu.html ← Panel de navegación
│ ├── listar.html ← Listado de registros
│ ├── crear.html ← Formulario de alta
│ ├── actualizar.html ← Formulario de modificación
│ ├── eliminar.html ← Confirmación de baja
│ └── reporte.html ← Informe de datos
└── .gitignore ← Excluye node_modules y .env del repositorio

7.1 Contenido de .gitignore

Archivo — .gitignore
# Carpeta de paquetes — se regenera con npm install
node_modules/

# Credenciales Oracle — nunca exponer contraseñas en el repositorio
.env

# Archivos temporales del sistema
*.log
.DS_Store
La carpeta node_modules puede tener cientos de MB. Nunca se copia ni se sube a GitHub. Solo se sube el código fuente y el compañero ejecuta npm install para regenerarla.

Instalación de dependencias con npm

Una vez creada la estructura, instalar los paquetes necesarios para el proyecto WEB.

8.1 Instalar paquetes del proyecto

PowerShell — Instalar dependencias (ejecutar dentro de js\)
# Ir a la carpeta js del proyecto
cd C:\proyecto_web\js

# Instalar las 4 dependencias del proyecto
npm install express    # Servidor web y manejo de rutas
npm install oracledb   # Driver Oracle para Node.js
npm install dotenv     # Leer variables de entorno desde .env
npm install cors       # Permitir peticiones entre dominios distintos

# Instalar nodemon solo en desarrollo (reinicio automático al guardar)
npm install nodemon --save-dev

8.2 Qué hace cada paquete

PaqueteFunción en el proyectoDónde se usa
expressCrea el servidor HTTP y define las rutas de la API (GET, POST, PUT, DELETE).server.js
oracledbConecta Node.js con Oracle XE. Ejecuta SELECT, INSERT, UPDATE, DELETE.server.js
dotenvLee el archivo .env y carga las credenciales Oracle como variables del proceso.server.js (al inicio)
corsPermite que el HTML del navegador haga peticiones al servidor Node.js.server.js
nodemonReinicia el servidor automáticamente cada vez que se guarda un cambio en el código.Solo en desarrollo

Iniciar, reiniciar y detener el servidor

9.1 Iniciar el servidor

PowerShell — Formas de iniciar el servidor
# IMPORTANTE: siempre ejecutar desde dentro de la carpeta js\
cd C:\proyecto_web\js

# Opción 1 — Inicio directo con Node.js (producción)
node server.js

# Opción 2 — Con el script definido en package.json
npm start

# Opción 3 — Con nodemon (desarrollo, reinicio automático al guardar)
npm run dev
Servidor iniciado en http://localhost:3000
Conectado a Oracle XE — XEPDB1

9.2 Detener el servidor

PowerShell — Detener el servidor
# Detener el servidor desde la terminal donde está corriendo:
Ctrl + C

# Si el proceso quedó colgado y no responde al Ctrl+C,
# buscar qué proceso usa el puerto 3000:
netstat -ano | findstr :3000

# Terminar el proceso por su PID (reemplazar 12345 por el PID real):
Stop-Process -Id 12345 -Force

9.3 Verificar que el servidor está corriendo

PowerShell — Verificar proceso Node.js activo
# Ver si hay un proceso node.js corriendo
Get-Process -Name node -ErrorAction SilentlyContinue

# Verificar si el puerto 3000 está en uso
Test-NetConnection localhost -Port 3000
Mientras trabaja, deje el servidor corriendo con npm run dev (nodemon). Cada vez que guarde server.js, nodemon reiniciará el servidor automáticamente.

Modo Thin vs Modo Thick en oracledb

El driver oracledb para Node.js puede conectarse a Oracle en dos modos. Es importante entender cuál usar en el laboratorio:

Modo Thin (v6+) — Recomendado
  • No requiere instalar Oracle Client por separado.
  • Funciona con oracledb v6 o superior.
  • Se activa por defecto al no llamar initOracleClient().
  • Suficiente para todas las prácticas de PR2.
  • Más sencillo de configurar en el laboratorio.
Modo Thick — Avanzado
  • Requiere Oracle Instant Client o Oracle XE instalado.
  • Necesita llamar a oracledb.initOracleClient().
  • Habilita funciones avanzadas (Advanced Queuing, SODA).
  • Útil si Oracle XE ya está instalado en el mismo equipo.
  • Puede activarse automáticamente si detecta Oracle en el PATH.

10.1 Cómo usar el Modo Thin (sin configuración extra)

JavaScript — server.js · Conexión en Modo Thin
// Modo Thin: no llamar initOracleClient()
// oracledb v6+ lo activa automáticamente
const oracledb = require('oracledb');
require('dotenv').config();

const config = {
    user:          process.env.DB_USER,
    password:      process.env.DB_PASSWORD,
    connectString: process.env.DB_CONNECT   // localhost:1521/XEPDB1
};

async function probarConexion() {
    let conn;
    try {
        conn = await oracledb.getConnection(config);
        const result = await conn.execute('SELECT USER FROM dual');
        console.log('Conectado como:', result.rows[0][0]);
    } catch (err) {
        console.error('Error de conexión:', err.message);
    } finally {
        if (conn) await conn.close();
    }
}

probarConexion();

Errores frecuentes y soluciones

Error o síntomaCausa probableSolución
node no se reconoceNode.js no está instalado o el PATH no se actualizó.Cerrar y reabrir PowerShell. Reinstalar si persiste.
npm no se reconocenpm no está en el PATH (raro si se usó el MSI).Reinstalar Node.js con el instalador MSI oficial.
Cannot find module 'express'No se ejecutó npm install en la carpeta correcta.Entrar a js\ y ejecutar npm install.
EADDRINUSE :::3000El puerto 3000 ya está ocupado por otra instancia del servidor.Ejecutar netstat -ano | findstr :3000 y terminar el proceso.
ORA-12541: no listenerOracle XE no está iniciado o el listener está detenido.Iniciar OracleServiceXE y el listener desde PowerShell.
ORA-01017: invalid credentialsUsuario, contraseña o servicio incorrecto en el .env.Verificar DB_USER, DB_PASSWORD y DB_CONNECT en el .env.
Error: .env no cargaSe llama require('dotenv').config() después de usar process.env.Poner require('dotenv').config() en la primera línea de server.js.
Module not found: oracledbPaquete no instalado o instalado en otra carpeta.Confirmar que está dentro de js\ y ejecutar npm install oracledb.
nodemon no se reconoceSe instaló como dependencia local, no global.Usar npm run dev (definido en package.json) en lugar de nodemon directo.

Checklist final — antes de continuar con Oracle

Verificar cada punto antes de pasar a conectar Node.js con Oracle XE:

  • Node.js LTS instalado y verificado con node --version.
  • npm instalado y verificado con npm --version.
  • Servidor "Hola Mundo" ejecutado correctamente en http://localhost:3000.
  • Carpeta del proyecto creada con subcarpetas js\ y public\.
  • npm init -y ejecutado dentro de js\.
  • Paquetes instalados: express, oracledb, dotenv, cors, nodemon.
  • Archivo .env creado con las credenciales de Oracle XE.
  • Archivo .gitignore creado con node_modules/ y .env.
  • Scripts start y dev definidos en package.json.
  • Oracle XE iniciado y XEPDB1 disponible (verificado en Fase 1).
