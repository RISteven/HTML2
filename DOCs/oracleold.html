Oracle XE 21c — Características y Requisitos

Oracle Express Edition 21c (XE) es la versión gratuita de Oracle Database. Es ideal para aprendizaje, desarrollo y proyectos académicos.

RecursoLímite en XEImpacto en clase
CPUs2 CPUs máximoSuficiente para desarrollo
RAM (BD)2 GB para la baseLímite el poolMax de Node.js
Disco12 GB datos usuarioMás que suficiente para proyectos
PDBs1 Pluggable DatabaseUsamos XEPDB1 (pre-creada)

Rutas y servicios en Windows

ElementoRuta / Nombre
ORACLE_HOMEC:\app\<usuario>\product\21c\dbhomeXE
DatosC:\app\<usuario>\oradata\XE\
Alert LogC:\app\<usuario>\diag\rdbms\xe\XE\trace\alert_XE.log
Data PumpC:\app\<usuario>\admin\XE\dpdump\

ListenerOracleOraDB21Home1TNSListener

La PDB XEPDB1 se crea automáticamente al instalar Oracle XE. No es necesario crearla manualmente. Solo hay que abrirla y usarla.

Conexión a Oracle XE — SQLPlus (CLI) y DBeaver (GUI)

✅ SQLPlus — Usar cuando...
  • Scripts de despliegue y migración
  • Automatización y backups (expdp)
  • Examen práctico sin interfaz gráfica
  • Servidor sin entorno visual
  • Comandos de administración del sistema
✅ DBeaver — Usar cuando...
  • Explorar visualmente tablas y datos
  • Editar Triggers y Procedures
  • Ver diagrama ER de relaciones
  • Comparar datos en grilla editable
  • Exportar resultados a CSV/Excel

Parte A — Conexión con SQLPlus

PowerShell / CMD
-- Como SYSDBA (administrador total):
sqlplus / as sysdba
sqlplus sys/Oracle21c#@localhost:1521/XE as sysdba

-- Conexión directa a XEPDB1 (la PDB del proyecto):
sqlplus sys/Oracle21c#@localhost:1521/XEPDB1 as sysdba
sqlplus admin_web/AdminWeb2024#@localhost:1521/XEPDB1

-- Ejecutar script SQL sin abrir sesión interactiva:
sqlplus -s admin_web/AdminWeb2024#@localhost:1521/XEPDB1 @"C:\scripts\tablas.sql"
PowerShell — Función reutilizable
function Invoke-OracleXE {
    param(
        [string]$Usuario  = "admin_web",
        [string]$Password = "AdminWeb2024#",
        [string]$Servicio = "XEPDB1",
        [string]$SQL
    )
    $conn = "$Usuario/$Password@localhost:1521/$Servicio"
    $input = "SET FEEDBACK OFF`n$SQL`nEXIT;"
    return ($input | sqlplus -s $conn)
}

# Uso:
Invoke-OracleXE -SQL "SELECT table_name FROM user_tables ORDER BY 1;"

Parte B — Conexión con DBeaver

  1. Instalar DBeaver Community (gratuito) desde dbeaver.io/download
  2. Abrir DBeaver → File → New → Database Connection (Ctrl+Shift+N)
  3. Seleccionar Oracle → Next. DBeaver descarga el driver JDBC automáticamente.
  4. Completar los campos: Host: localhost | Port: 1521 | Database: XEPDB1 | Username: admin_web | Password: AdminWeb2024#
  5. Hacer clic en Test Connection → debe mostrar "Connected" → Finish
Para conectarse como SYSDBA en DBeaver: usar Username sys, Password Oracle21c#, y en Role seleccionar SYSDBA.

La PDB XEPDB1 — Base de Datos del Proyecto

En Oracle XE 21c la instalación crea automáticamente la arquitectura Multitenant: el CDB (contenedor raíz XE) y la PDB (XEPDB1) donde se trabajan todos los objetos del proyecto.

SQLPlus — Verificar y abrir XEPDB1
-- Conectarse como SYSDBA al CDB:
sqlplus sys/Oracle21c#@localhost:1521/XE as sysdba

-- Ver estado de las PDBs:
SELECT con_id, name, open_mode FROM v$pdbs;

-- Si XEPDB1 aparece en MOUNTED, abrirla:
ALTER PLUGGABLE DATABASE XEPDB1 OPEN;

-- Guardar estado para que abra automáticamente al reiniciar Oracle:
ALTER PLUGGABLE DATABASE XEPDB1 SAVE STATE;

-- Verificar el contenedor activo:
SHOW CON_NAME;   -- Debe mostrar: XEPDB1
Si Oracle XE se reinicia y XEPDB1 no abre, ejecutar ALTER PLUGGABLE DATABASE XEPDB1 SAVE STATE para persistir el estado de apertura.

Creación de Usuarios

Los usuarios en Oracle XE 21c deben crearse conectados a XEPDB1, no en el CDB raíz. En XEPDB1 no se usa el prefijo C##.
SQLPlus — Conectarse a XEPDB1 como SYSDBA
sqlplus sys/Oracle21c#@localhost:1521/XEPDB1 as sysdba
SHOW CON_NAME;   -- Verificar: debe decir XEPDB1
SQL — Crear usuarios del proyecto
-- Administrador del proyecto:
CREATE USER admin_web
  IDENTIFIED BY AdminWeb2024#
  DEFAULT TABLESPACE users
  TEMPORARY TABLESPACE temp
  QUOTA UNLIMITED ON users;

-- Desarrollador:
CREATE USER dev_web
  IDENTIFIED BY DevWeb2024#
  DEFAULT TABLESPACE users
  TEMPORARY TABLESPACE temp
  QUOTA 500M ON users;

-- Usuario para Node.js (app):
CREATE USER app_web
  IDENTIFIED BY AppWeb2024#
  DEFAULT TABLESPACE users
  TEMPORARY TABLESPACE temp
  QUOTA 200M ON users;

-- Solo lectura (reportes):
CREATE USER reporte_web
  IDENTIFIED BY Reporte2024#
  DEFAULT TABLESPACE users
  TEMPORARY TABLESPACE temp
  QUOTA 0 ON users;

-- Verificar usuarios creados:
SELECT username, account_status, default_tablespace,
       TO_CHAR(created, 'DD/MM/YYYY') AS creado
FROM   dba_users
WHERE  username IN ('ADMIN_WEB','DEV_WEB','APP_WEB','REPORTE_WEB')
ORDER BY created;

-- Otras operaciones:
ALTER USER dev_web IDENTIFIED BY NuevaPass2024#;  -- Cambiar contraseña
ALTER USER dev_web ACCOUNT UNLOCK;                  -- Desbloquear
DROP USER  dev_web CASCADE;                          -- Eliminar con objetos
En DBeaver: conexión SYSDBA → XEPDB1 → Security → Users → click derecho → Create New User.

Creación de Esquemas

En Oracle el esquema = usuario. Al crear un usuario se crea automáticamente un esquema vacío con el mismo nombre. Las tablas que se crean bajo ese usuario forman su esquema.

SQL — Trabajar con esquemas
-- Conectarse al esquema principal:
sqlplus admin_web/AdminWeb2024#@localhost:1521/XEPDB1

-- Ver en qué esquema/contenedor estamos:
SHOW USER;
SELECT SYS_CONTEXT('USERENV','CURRENT_USER')   AS usuario,
       SYS_CONTEXT('USERENV','CURRENT_SCHEMA') AS esquema,
       SYS_CONTEXT('USERENV','CON_NAME')        AS contenedor
FROM   dual;

-- Ver todos los objetos del esquema:
SELECT object_type, object_name, status
FROM   user_objects
ORDER BY object_type, object_name;

-- Cambiar de esquema sin cerrar sesión:
ALTER SESSION SET CURRENT_SCHEMA = admin_web;

-- Crear sinónimo público (acceso entre esquemas):
CREATE PUBLIC SYNONYM productos FOR admin_web.productos;

Conectarse como admin_web a XEPDB1 antes de ejecutar los CREATE TABLE. En DBeaver: SQL Editor sobre la conexión admin_web.

);
SQL — Tabla USUARIOS
CREATE TABLE usuarios (
    usuario_id     NUMBER        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    rol_id         NUMBER        NOT NULL,
    nombre         VARCHAR2(100) NOT NULL,
    apellido       VARCHAR2(100) NOT NULL,
    email          VARCHAR2(150) NOT NULL,
    username       VARCHAR2(50)  NOT NULL,
    password_hash  VARCHAR2(256) NOT NULL,
    telefono       VARCHAR2(20),
    activo         CHAR(1)       DEFAULT 'S' NOT NULL,
    fecha_registro DATE          DEFAULT SYSDATE NOT NULL,
    ultimo_acceso  TIMESTAMP,
    CONSTRAINT usuarios_email_uq    UNIQUE (email),
    CONSTRAINT usuarios_username_uq UNIQUE (username),
    CONSTRAINT usuarios_activo_ck   CHECK (activo IN ('S','N')),
    CONSTRAINT usuarios_rol_fk      FOREIGN KEY (rol_id) REFERENCES roles(rol_id)
);
SQL — Tablas CATEGORIAS, PRODUCTOS, PEDIDOS, DETALLE, SESIONES, LOGS
CREATE TABLE categorias (
    categoria_id  NUMBER        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre        VARCHAR2(100) NOT NULL,
    descripcion   VARCHAR2(300),
    imagen_url    VARCHAR2(500),
    activo        CHAR(1)       DEFAULT 'S' NOT NULL,
    fecha_creacion DATE         DEFAULT SYSDATE NOT NULL,
    CONSTRAINT categorias_nombre_uq UNIQUE (nombre),
    CONSTRAINT categorias_activo_ck CHECK (activo IN ('S','N'))
);

CREATE TABLE productos (
    producto_id         NUMBER        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    categoria_id        NUMBER        NOT NULL,
    nombre              VARCHAR2(200) NOT NULL,
    descripcion         CLOB,
    precio              NUMBER(10,2)  NOT NULL,
    stock               NUMBER(6)     DEFAULT 0 NOT NULL,
    imagen_url          VARCHAR2(500),
    activo              CHAR(1)       DEFAULT 'S' NOT NULL,
    fecha_creacion      DATE          DEFAULT SYSDATE NOT NULL,
    fecha_actualizacion DATE          DEFAULT SYSDATE,
    CONSTRAINT productos_precio_ck CHECK (precio >= 0),
    CONSTRAINT productos_stock_ck  CHECK (stock  >= 0),
    CONSTRAINT productos_activo_ck CHECK (activo IN ('S','N')),
    CONSTRAINT productos_cat_fk    FOREIGN KEY (categoria_id) REFERENCES categorias(categoria_id)
);

CREATE TABLE pedidos (
    pedido_id       NUMBER        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    usuario_id      NUMBER        NOT NULL,
    estado          VARCHAR2(20)  DEFAULT 'PENDIENTE' NOT NULL,
    total           NUMBER(12,2)  DEFAULT 0 NOT NULL,
    direccion_envio VARCHAR2(400),
    notas           VARCHAR2(500),
    fecha_pedido    DATE          DEFAULT SYSDATE NOT NULL,
    fecha_entrega   DATE,
    CONSTRAINT pedidos_estado_ck  CHECK (estado IN ('PENDIENTE','PROCESANDO','ENVIADO','ENTREGADO','CANCELADO')),
    CONSTRAINT pedidos_usuario_fk FOREIGN KEY (usuario_id) REFERENCES usuarios(usuario_id)
);

CREATE TABLE detalle_pedidos (
    detalle_id      NUMBER       GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    pedido_id       NUMBER       NOT NULL,
    producto_id     NUMBER       NOT NULL,
    cantidad        NUMBER(4)    NOT NULL,
    precio_unitario NUMBER(10,2) NOT NULL,
    subtotal        NUMBER(12,2) GENERATED ALWAYS AS (cantidad * precio_unitario) VIRTUAL,
    CONSTRAINT detalle_cantidad_ck  CHECK (cantidad > 0),
    CONSTRAINT detalle_pedido_fk    FOREIGN KEY (pedido_id)   REFERENCES pedidos(pedido_id),
    CONSTRAINT detalle_producto_fk  FOREIGN KEY (producto_id) REFERENCES productos(producto_id),
    CONSTRAINT detalle_uq           UNIQUE (pedido_id, producto_id)
);

-- Índices para optimizar consultas:
CREATE INDEX idx_usuarios_email   ON usuarios(email);
CREATE INDEX idx_productos_cat    ON productos(categoria_id);
CREATE INDEX idx_pedidos_usuario  ON pedidos(usuario_id);
CREATE INDEX idx_pedidos_estado   ON pedidos(estado);
CREATE INDEX idx_detalle_pedido   ON detalle_pedidos(pedido_id);

Triggers — CLI y DBeaver

Un trigger es código PL/SQL que se ejecuta automáticamente antes o después de un INSERT, UPDATE o DELETE sobre una tabla. No requiere llamada explícita.

PL/SQL — Trigger 1: Registrar en logs_acceso al crear usuario
CREATE OR REPLACE TRIGGER trg_log_nuevo_usuario
    AFTER INSERT ON usuarios
    FOR EACH ROW
BEGIN
    INSERT INTO logs_acceso (usuario_id, accion, descripcion, resultado)
    VALUES (
        :NEW.usuario_id,
        'REGISTRO',
        'Nuevo usuario: ' || :NEW.username || ' (' || :NEW.email || ')',
        'S'
    );
END;
/
PL/SQL — Trigger 2: Actualizar fecha_actualizacion al modificar producto
CREATE OR REPLACE TRIGGER trg_producto_actualizado
    BEFORE UPDATE ON productos
    FOR EACH ROW
BEGIN
    :NEW.fecha_actualizacion := SYSDATE;
END;
/
PL/SQL — Trigger 3: Validar que el stock no sea negativo
CREATE OR REPLACE TRIGGER trg_validar_stock
    BEFORE UPDATE OF stock ON productos
    FOR EACH ROW
BEGIN
    IF :NEW.stock < 0 THEN
        RAISE_APPLICATION_ERROR(-20001,
            'Error: stock negativo. Producto ID: ' || :OLD.producto_id);
    END IF;
END;
/
PL/SQL — Trigger 4: Actualizar total del pedido automáticamente
CREATE OR REPLACE TRIGGER trg_actualizar_total_pedido
    AFTER INSERT OR UPDATE OR DELETE ON detalle_pedidos
    FOR EACH ROW
DECLARE
    v_pedido_id NUMBER;
BEGIN
    v_pedido_id := CASE
        WHEN INSERTING OR UPDATING THEN :NEW.pedido_id
        ELSE :OLD.pedido_id
    END;

    UPDATE pedidos
    SET    total = (
               SELECT NVL(SUM(cantidad * precio_unitario), 0)
               FROM   detalle_pedidos
               WHERE  pedido_id = v_pedido_id
           )
    WHERE  pedido_id = v_pedido_id;
END;
/
SQL — Gestión de triggers
-- Ver todos los triggers del esquema:
SELECT trigger_name, table_name, trigger_type, triggering_event, status
FROM   user_triggers ORDER BY table_name;

-- Habilitar / Deshabilitar:
ALTER TRIGGER trg_log_nuevo_usuario ENABLE;
ALTER TRIGGER trg_log_nuevo_usuario DISABLE;

-- Ver errores de compilación:
SHOW ERRORS TRIGGER trg_validar_stock;
SELECT * FROM user_errors WHERE name = 'TRG_VALIDAR_STOCK';
Desde DBeaver: expandir tabla → Triggers → doble click para editar el cuerpo PL/SQL con resaltado de sintaxis → Ctrl+S para guardar.

Consultas de Registros

SQL — Consultas con JOIN y funciones
-- Usuarios con su rol:
SELECT u.usuario_id,
       u.nombre || ' ' || u.apellido AS nombre_completo,
       r.nombre AS rol, u.activo
FROM   usuarios u
JOIN   roles r ON u.rol_id = r.rol_id
ORDER BY u.nombre;

-- Productos activos con precio formateado:
SELECT c.nombre AS categoria, p.nombre,
       TO_CHAR(p.precio, 'FM999,999,990') || ' Gs.' AS precio,
       p.stock
FROM   productos p
JOIN   categorias c ON p.categoria_id = c.categoria_id
WHERE  p.activo = 'S' AND p.stock > 0
ORDER BY c.nombre, p.nombre;

-- Top 5 productos más vendidos:
SELECT p.nombre, SUM(dp.cantidad) AS vendidos
FROM   detalle_pedidos dp
JOIN   productos p ON dp.producto_id = p.producto_id
GROUP BY p.nombre
ORDER BY vendidos DESC
FETCH FIRST 5 ROWS ONLY;

-- Resumen de ventas por categoría:
SELECT c.nombre AS categoria,
       COUNT(DISTINCT dp.pedido_id)  AS pedidos,
       SUM(dp.cantidad)              AS unidades,
       SUM(dp.subtotal)              AS ingresos
FROM   detalle_pedidos dp
JOIN   productos pr  ON dp.producto_id  = pr.producto_id
JOIN   categorias c  ON pr.categoria_id = c.categoria_id
JOIN   pedidos ped   ON dp.pedido_id    = ped.pedido_id
WHERE  ped.estado != 'CANCELADO'
GROUP BY c.nombre
ORDER BY ingresos DESC;

-- Paginación moderna (Oracle 12c+):
SELECT nombre, precio, stock
FROM   productos WHERE activo = 'S'
ORDER BY nombre
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY;

Validación de Tablas y Estructura

SQL — Validar estructura, constraints e integridad
-- Ver estructura de una tabla (solo SQLPlus):
DESC usuarios;
DESC productos;

-- Listar tablas del esquema:
SELECT table_name, num_rows, last_analyzed
FROM   user_tables ORDER BY table_name;

-- Ver constraints y tipos:
SELECT constraint_name, constraint_type, table_name, status
FROM   user_constraints ORDER BY table_name, constraint_type;

-- Ver Foreign Keys y sus referencias:
SELECT uc.table_name AS tabla_origen,
       ucc.column_name AS columna,
       uc2.table_name  AS tabla_ref
FROM   user_constraints  uc
JOIN   user_cons_columns ucc  ON uc.constraint_name   = ucc.constraint_name
JOIN   user_constraints  uc2  ON uc.r_constraint_name = uc2.constraint_name
WHERE  uc.constraint_type = 'R' ORDER BY uc.table_name;

-- Contar registros en todas las tablas:
SELECT 'roles'           AS tabla, COUNT(*) AS n FROM roles          UNION ALL
SELECT 'usuarios',                  COUNT(*)              FROM usuarios        UNION ALL
SELECT 'categorias',                COUNT(*)              FROM categorias      UNION ALL
SELECT 'productos',                 COUNT(*)              FROM productos       UNION ALL
SELECT 'pedidos',                   COUNT(*)              FROM pedidos         UNION ALL
SELECT 'detalle_pedidos',           COUNT(*)              FROM detalle_pedidos UNION ALL
SELECT 'logs_acceso',               COUNT(*)              FROM logs_acceso
ORDER BY tabla;

-- Verificar totales calculados por triggers:
SELECT ped.pedido_id,
       ped.total                      AS total_trigger,
       SUM(dp.subtotal)              AS total_calculado,
       ped.total - SUM(dp.subtotal) AS diferencia
FROM   pedidos ped
JOIN   detalle_pedidos dp ON ped.pedido_id = dp.pedido_id
GROUP BY ped.pedido_id, ped.total
HAVING ABS(ped.total - SUM(dp.subtotal)) > 0.01;
En DBeaver: Click derecho sobre el esquema → View Diagram para ver el ERD con todas las relaciones FK de forma visual.
